# 玩家关键字搜索 · 4.0.3

本次仅调整玩家 / 战队查找、前端缓存版本和交付版本信息。应用版本为 4.0.3；`VERSION` 为版本号文件，网页顶部同步显示。网站无需构建，启动方法见根 README。

## 研究结论与证据边界

提供的 `xiaoxiaowu.apk`：包名 `com.wlf.app`，versionName 7.25，versionCode 95。DEX 的 `MainActivity.buildHost` 创建字节数组，交给 `W1.b` 逐字节异或 90 解码入口地址；`initWebView` 最终使用 `WebView.loadUrl(HOME_URL)`。APK 未内嵌玩家搜索页面或玩家索引。查到的个人中心、战绩页面会转到登录页，因此未读取其登录后的玩家搜索请求，也未能证明其后端使用何种模糊匹配算法。

为避免猜测，另外核对舞立方官方网页的实际搜索代码：

- 官方入口：https://dancewebdemo.shenghuayule.com/dance/
- 搜索模块：https://dancewebdemo.shenghuayule.com/dance/static/js/pages-home-search.af82cce2.js
- `onSearch` 将关键字进行 URL 编码后发送至 `/api/Common/Search`，参数为 `keyword`、`type`、`page`、`pagesize`。
- type=0：玩家和战队；type=1：玩家；type=2：战队。响应 `List` 的 Type=1 为玩家、Type=2 为战队，ID 用于打开详情。
- 官方页面按服务端返回结果展示，非客户端全名相等比较；翻页到空列表后停止。短页不一定代表结束。
- 可以确认关键字查询协议；无法从客户端证明服务端使用 SQL LIKE、分词、拼音、编辑距离或其他实现。本版本不承诺拼音、错字容错或所有关键字必有结果，不扫描全站玩家目录。

## 本次实现

- 明确“昵称关键字”入口：输入昵称的一部分并按回车或搜索。保留内部空格、外文、数字昵称和特殊符号，由现有 URLSearchParams 编码发送；不把数字昵称自动变成 ID。
- 新增“玩家和战队”合并查询；仍保留独立玩家、战队和精确 ID。
- 返回结果按类型与 ID 去重，修正字段兼容，突出显示关键字（输出先转义，防止 HTML 注入）。结果不使用本地字面匹配二次过滤，以免丢掉官方返回的模糊匹配。
- 无总数时继续查询到空页，有有效总数时按总数停止；空结果、失败和响应格式异常分别显示。
- 翻页使用已提交条件；更改条件清空旧结果和页码；取消旧请求并阻止旧响应覆盖；失败可重试。只读取公开资料，保留原登录和隐私限制。
